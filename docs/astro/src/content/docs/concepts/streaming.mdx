---
title: Streaming
description: Text buffering and incremental synthesis.
---

A Rust `Stream` binds a model and voice to a request. `add_text` appends input;
`force_generate` makes buffered text ready, and `finish` forces the remaining input
and marks the stream finished.

The scheduler prepares text when its character count exceeds the current schedule
entry or its deadline expires. The deadline starts when input fills an empty buffer;
every append does not reset it.

One model call per stream runs at a time. Active text units remain pinned to their
model instance. Different streams may share batches of Start or Continue operations.

`recv` returns an audio chunk, an end marker as `None`, or an error.
An end marker can mean the current input is drained; `finish` marks the final end.
See [Stream](/api/tts-stream) and [Engine](/api/streaming-tts).
